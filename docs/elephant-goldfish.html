vii-stack · /vii-goldfish

Design with an elephant. Review with a goldfish.

The agent that wrote your plan remembers too much to review it. It reads "the queue" and knows which queue you mean. The engineer or agent who builds from the plan won't know. So the plan goes to reviewers who remember nothing, and they point out every place it relies on context that was never written down.

The lenses

LensThe goldfish asksCatches
comprehensionExplain it back in your own words. Where did you have to guess?Undefined terms, pronouns with no clear referent
gapsWhat does an implementer need that isn't here?Missing error cases, limits, owners, inputs

      How the visual report is built

      The HTML report is not written by hand on each run. The skill includes one fixed template, report-template.html. On each run the elephant only fills in a block of JSON, and the template's script draws the page from that JSON. So every report looks the same, and you can open any of them offline with a double-click.

      The stat tiles at the top of the report are worked out in the browser from the same JSON: goldfish count, findings, HIGHs, fix vs contest, and predictions confirmed vs blind spots found. Filter buttons narrow the list by severity, verdict or lens. Text goes into the page with textContent, never as raw HTML, so a goldfish that quotes markup can't break the page.

      For developers: how it works underneath

      In Claude Code the goldfish are plain Agent tool calls. They're all sent in one message, so they run in parallel, and each one starts as a fresh agent. The whole pattern depends on one rule: the goldfish prompt carries no context. It gets a file path, a lens and an output format, and nothing else.

      ChoiceWhy
      Fresh subagent, never a forkA fork inherits the elephant's memory, so it would just be a second elephant
      No summary in the promptA summary leaks exactly the context you're testing for. If it matters, it belongs in the doc.
      Doc plus its links, no repo searchThat's how an implementer starting from the doc would read it
      Max 6 findings per goldfishKeeps it to the worst problems. Goldfish are noisy by design.
      Stop if subagents are unavailableA review run in the author's own context isn't a goldfish review

      Using the pattern in your own app

      Outside Claude Code, a goldfish is just an API call whose message history holds nothing but the document. Here's the same idea with the Anthropic TypeScript SDK:

      import Anthropic from "@anthropic-ai/sdk";
const client = new Anthropic();

const lenses = {
  comprehension: "Explain it back. Where did you have to guess?",
  gaps: "What does an implementer need that is not here?",
  buildability: "Could you start coding tomorrow? First question?",
};

// Each call starts with an empty history: that is the goldfish.
const reviews = await Promise.all(Object.entries(lenses).map(([lens, q]) =>
  client.messages.create({
    model: "claude-opus-5-5",
    max_tokens: 2000,
    messages: [{ role: "user",
      content: `You have never seen this project.\nLens: ${lens} — ${q}\n` +
               `Report at most 6 findings as [HIGH|MED|LOW] where — issue — need.\n\n${doc}` }],
  })));

// The elephant (your app, with full context) triages reviews into FIX / CONTEST.
